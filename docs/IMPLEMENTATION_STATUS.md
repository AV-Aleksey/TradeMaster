# Текущая реализация

> Актуальное упрощение конструктора: [CURRENT_SIGNALS.md](CURRENT_SIGNALS.md). Пять индикаторов, группы И / ИЛИ, без временных окон и цепочек; две начальные схемы вверх / вниз. Прежние описания этих возможностей ниже относятся к предыдущему объёму.

Обновлено: 4 ноября 2026 года. Это статус проверенного кода, а не замена полного [плана](IMPLEMENTATION_PLAN.md).

## Что работает

- Electron + React + TypeScript, Ant Design, React Query Builder и KLineCharts. `npm start` собирает и открывает desktop-приложение; `npm run dev` запускает режим разработки.
- Пары, переключение источника у пары, свечной график, отдельные переключатели сигналов и общий мониторинг. График работает при выключенном мониторинге.
- SQLite сохраняет пары, схемы и события. После перезапуска мониторинг выключен; сохранённые флаги сигналов восстанавливаются. Пауза не создаёт событий за пропущенный период.
- Редактор вложенных И / ИЛИ, разные таймфреймы, сравнения, пересечения, рост/снижение, сдвиги и множители. Для пересечения интерфейс ограничивает второй ряд тем же таймфреймом. Есть копирование варианта и справка «Как составить сигнал».
- Режим «Цепочка подтверждений»: отдельный триггер, параллельные или последовательные этапы, все/любое параллельное подтверждение, запоминание/перепроверка, общее окно, смена порядка этапов, сброс, итоговый фильтр, повторный триггер и cooldown. Карточка показывает ход ожидания; событие сохраняет время триггера и дерево подтверждений.
- Временные окна И/ИЛИ и отдельных условий относительно текущей свечи или триггера, включая поиск до триггера; только закрытые данные, без вложенных окон. Итоговые метки с явной обработкой unknown и отношение средних объёмов участков. Обе цепочки README доступны как обычные шаблоны: [точная конфигурация](README_SIGNALS.md).
- Реестр расчётов и метаданных: OHLCV, SMA/EMA/WMA, MACD, Stochastic, средний и суммарный объём, локальные максимум/минимум и подтверждённые фракталы. Индикатор и бюджет его истории задаются вместе.
- Настройки iTick: зашифрованный ключ, маска, показ по глазку, замена, Trial / Production и Ping. Расшифрованный ключ выдаётся в интерфейс по отдельному запросу просмотра, не включается в снимки состояния и очищается из просмотра при скрытии/закрытии настроек.
- Replay — явно обозначенные синтетические данные. iTick — REST-каталог, история, пагинация и обработка ошибок. Авторизация и загрузка реальных свечей Trial проверены; текущий ключ не принят Production. У проверенного тарифа свечной WebSocket отклонён, используется REST. Это не приёмка полноценного live-свечного потока.

## Семантика новых показателей

Локальный максимум — High последних N закрытых свечей; минимум — Low. В окно включена текущая закрытая свеча. Чтобы проверять пробой предыдущего окна, задайте правому показателю сдвиг 1.

Сумма объёма требует полного окна. Ноль — число, отсутствие объёма — «Нет данных». Единицы объёма разных поставщиков автоматически не приравниваются.

Фрактал с настройкой N+N проверяет строгое превосходство High / снижение Low относительно N свечей слева и справа. Он становится доступен на закрытии последней правой свечи, без переноса результата в прошлое. Равные вершины/впадины не подтверждаются.

Уровень последнего подтверждённого фрактала действует в пределах `fractalLookback` свечей, считая свечу подтверждения первой; по умолчанию 100, диапазон 1–10000. После истечения окна без нового подтверждения результат неизвестен. Значение 1 оставляет уровень только на свече подтверждения. Бюджет истории учитывает всё окно и обе стороны, поэтому добавление длинной истории другого сигнала не меняет результат. Разрыв свечей обрывает доступную историю и перенос уровня.

## Статус фаз

### Текущая семантика цепочек

Окно `timeoutBars` отсчитывается в закрытиях периода проверки сигнала, от триггера включительно: окно 3 допускает t0, t0+1, t0+2, t0+3. Последняя свеча проверяется до отмены. При 0 подтверждения возможны только на свече триггера. Срок цепочки общий; условия могут отдельно искать совпадения в пределах окна от текущей свечи или триггера, включая прошлые свечи. Индивидуальные дедлайны этапов с отсчётом от предыдущего этапа ещё не реализованы.

Параллельные подтверждения приходят в любом порядке; выбор «все» / «хотя бы одно» относится к группам, внутри каждой остаются И/ИЛИ. В последовательном режиме требуются все этапы по заданному порядку. По умолчанию они могут завершиться на одной свече; опция следующей свечи откладывает первое подтверждение после триггера и переходы между последовательными этапами.

Политика «Запомнить» сохраняет факт и его исходное объяснение. «Перепроверить» требует, чтобы ранее замеченный этап оставался истинным при завершении. Итоговый фильтр проверяется на каждой попытке завершения. После события цепочка закрывается; новый триггер — новый переход его дерева из false в true. Повторный триггер во время ожидания игнорируется либо заменяет цепочку, согласно настройке. Cooldown блокирует запуск слишком ранней новой цепочки, без отложенной отправки.

**Если условие сброса выключено**, цепочка всё равно закрывается после события или проверки последней свечи окна. Обратное пересечение не является скрытым условием сброса. Явный сброс имеет приоритет над триггером/завершением на одной свече. Если результат включённого сброса unknown, на этой свече не принимаются новые триггеры и подтверждения; окно продолжает идти. Пропущенный триггер требует свежего перехода.

Пауза, выключение, изменение схемы/источника отменяют незавершённые цепочки. Новый разрыв любого используемого ряда также отменяет цепочку. При недостающем баре синхронизация ждёт его, но если закрытый преемник уже доказывает пропуск, cursor продвигается с отменой и перепрогревом — без подстановки будущего значения в старую проверку. Подтверждённые факты не переносятся через разрыв.

Конфигурация цепочки сохраняется в SQLite и восстанавливается при запуске; активные факты сейчас живут в памяти. После перезапуска мониторинг выключен, начинается ожидание нового триггера. Аварийное восстановление активной цепочки из checkpoint — отдельный незавершённый блок. Предварительная загрузка учитывает все деревья и глубину окна; чрезмерная комбинация окна и таймфреймов отклоняется явно.

## Проверки

- `npm test` — расчёты, операторы, комбинации, отсутствие будущих данных, независимость сигналов, жизненный цикл, адаптеры и преобразование редактора.
- `npm run test:desktop` — окно Electron, preload, SQLite worker, график, сигналы, настройки, пары и восстановление после перезапуска.
- `npm run test:editor` — настройка и сохранение пользовательских фрактала, MACD и Stochastic через настоящий редактор.
- `npm run test:temporal` — создание цепочки, политики и порядок подтверждений, сброс/фильтр, редактирование без изменения смысла, исполнение на закрытии и восстановление конфигурации из SQLite.
- `npm run test:readme` — создание обоих шаблонов без дублей, редактирование с сохранением окон/меток и перезапуск SQLite.
- `npm run build` — TypeScript и production-сборка процессов.

Desktop-проверки используют отдельные профили и тестовые данные. Локальные проверки на macOS не доказывают работоспособность Windows или упакованного установщика. Синтетика не подтверждает торговую результативность.
