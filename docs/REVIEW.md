# Проверка идеи и соответствия схеме README

Дата: 4 ноября 2026 года. Проверены README и текущие SPEC/STACK/UI. Это анализ требований и торговой гипотезы; историческая доходность не рассчитывалась, данные с реального токена не получены.

## Вывод

**Архитектура позволяет реализовать схему из первой части README.** Основной алгоритм — цепочка событий с памятью, а не только набор одновременных И / ИЛИ. Он предусмотрен в SPEC, но требует предметного исполнения поверх готового редактора условий.

**Польза терминала как инструмента наблюдения обоснована сценарием:** отслеживать пары, повторяемо проверять формальные условия, видеть причины события и получать уведомление без постоянного просмотра графика. Это не доказательство прибыльности схемы. Торговое преимущество и преимущество метки «подтверждён» пока не установлены.

Главные вопросы перед точной реализацией: согласовать неоднозначности правил, проверить пригодность конкретных данных Finam и воспроизвести эталонные цепочки на истории.

React Query Builder предоставляет редактор групп и интеграцию с UI-kit. Наличие библиотеки не означает, что она автоматически реализует баровые окна и автомат подтверждений TradeMaster. Движок этих правил — необходимая часть реализации, совместимая с использованием готовых UI-компонентов. [Официальная документация](https://react-querybuilder.js.org/docs/compat).

## 2. Что нельзя оставить неоднозначным

### Пересечения при касании линий

EMA в README: предыдущее равенство допустимо, текущее пересечение строгое. Стохастик: предыдущее положение строгое, текущее равенство уже считается пересечением. Например, переход K/D из 81/80 в 79/79 удовлетворяет стохастическому правилу вниз из README, но не общему строгому оператору пересечения из SPEC.

Следовательно, для точного шаблона Stochastic используется явное выражение сравнений либо настройка политики касания. Один общий оператор с неизменяемыми неравенствами незаметно сдвинет событие. Нужны отдельные эталоны касания и пересечения для EMA и K/D.

### Событие в прошлом и состояние сейчас

Нужно различить время пребывания K в зоне, время пересечения K/D и момент проверки «продолжает расти/снижаться». Зона должна иметь согласованное положение относительно пересечения; поиск до кросса не может читать будущие свечи относительно текущего момента. Если событие найдено на t0−2, зафиксировать сигнал задним числом на t0−2 нельзя: цепочка начинается только на t0.

Также требуется решить, остаётся ли подтверждение действующим, если до прихода второго индикатора первый развернулся обратно. SPEC поддерживает оба режима, но шаблону нужно выбрать один. Нельзя выбирать вариант по тому, какой лучше выглядит на известном графике.

### Границы объёмных участков

Первая часть README делит участки по кроссу, вторая — по локальному минимуму. Это разные расчёты. Нужны точные начальная/конечная свечи, включение свечи кросса в один или оба участка, направление экстремума для каждой цепочки, разрешение одинаковых экстремумов и поведение при завершении на самой свече кросса.

Участок после кросса не обязательно является «отскоком»: после медвежьего кросса цена может продолжать снижаться. Отношение средних объёмов по таким участкам описывает их активность, а не автоматически силу покупателей/продавцов. Интерпретацию порогов 0.8/1.2 нужно проверять отдельно для двух направлений.

### Две версии алгоритма в одном README

Вторая часть содержит четыре независимых паттерна и cooldown 6 баров; первая — две цепочки с новым событием только от нового кросса. Нельзя одновременно считать обе части единственным эталоном. Они могут быть разными версиями/шаблонами. Значения SMA/EMA seed и утверждение о совпадении с TradingView также требуют контрольных данных: 110 баров дают доступность расчёта, но не гарантируют независимость EMA90 от начальной истории.

### Числа и время

От закрытия свечи триггера t0 до закрытия t0+3 проходит 15 минут на 5m, при совпадении на t0 — 0 минут. Формулировка README «5–20 минут» считает четыре свечи от начала первой; её нельзя трактовать как дополнительное ожидание после уже найденного кросса.

В примере издержек README `2 × 0.055 + 0.02 = 0.13` только если 0.02 — суммарное проскальзывание обоих исполнений. Если это значение на каждую сторону, результат 0.15. Новое SPEC задаёт четыре компонента отдельно; актуальные ставки для Finam ещё не установлены.

## 3. Польза и пределы торговой гипотезы

EMA, MACD и Stochastic вычисляются из одних и тех же ценовых данных, поэтому их совпадение нельзя считать тремя независимыми свидетельствами с перемножением вероятностей. Это вывод из формул README, а не измеренная корреляция для конкретной пары.

Дополнительные фильтры могут сократить количество событий и отложить их появление; улучшение последующего движения из этого не следует. Осциллятор может оставаться в экстремальной зоне при сильном тренде, а индикаторы запаздывают относительно движения. [Обучающий материал CME](https://www.cmegroup.com/education/courses/technical-analysis/oscillators-macd-rsi-stochastics).

Слово «подтверждён» здесь означает выполнение дополнительных формальных условий. Рост/падение EMA30/90 не является самостоятельным доказательством пробоя локальных максимумов/минимумов, а более высокая прибыльность такой группы событий ещё не измерена. В интерфейсе это название категории с объяснением, а не процент уверенности или обещание разворота.

Исходная схема — детектор события. Без правил входа, выхода и допустимого риска нельзя делать вывод о доходности полноценной торговой стратегии. Можно измерять последующие движения и ценность уведомления; моделирование сделки требует отдельно согласованных правил и исполнимых цен со спредом, комиссиями и задержкой реакции.

## 4. Перенос SUI/USDC → EUR/USD / Finam

Это перенос логики на другой рынок, а не воспроизведение прежних данных. Наличие именно SUI/USDC и пригодность данных конкретного инструмента у Finam не подтверждены. Нужны реальный код инструмента, тип данных, права, задержка, календарь и значения объёма.

FX — внебиржевой рынок: объём отдельного потока нельзя автоматически трактовать как объём всего EUR/USD. [Описание структуры FX от BIS](https://www.bis.org/publications/working-paper-1094-foreign-exchange-market). На публичной странице EUR/USD Finam поле объёма в прочитанном снимке равно 0; это предупреждающий пример, **не доказательство**, что доступный пользователю Trade API всегда возвращает ноль. [Страница Finam](https://www.finam.ru/quote/forex/eurusd/).

Если объём отсутствует, недостоверен или является другим типом величины, нельзя подставлять его в прежние пороги и выдавать прежнюю метку подтверждения. Нужна явная несовместимость либо отдельная версия схемы без объёмного фильтра/с другим определением. Это изменение гипотезы, которое тестируется заново.

В опубликованном REST-описании внутридневная история M5–H8 имеет глубину 30 дней. Для исследования более длинного периода нужны архив/импорт; иной транспорт не следует считать способом автоматически убрать ограничение исторического источника. [Bars Finam](https://api.finam.ru/docs/rest/#marketdataservice_bars).

## 5. Как проверить пользу

1. Зафиксировать однозначную версию двух цепочек; подготовить ручные примеры с точным ожидаемым временем и объяснением события, а также случаи сброса и несрабатывания.
2. На фактическом выбранном инструменте проверить OHLCV, объём, расписание, завершение свечей и соответствие графику. Отдельно сохранять источник/ревизию и единицы.
3. Сравнить на одних данных: один кросс EMA; кросс + Stochastic; кросс + MACD; оба подтверждения; отдельно категории фона/объёма. Это покажет, какой блок добавляет пользу, какие события он исключает и сколько задержки вносит. Добавить контрольные случайные моменты, сопоставимые по режиму сессий.
4. Измерять частоту, задержку от триггера, долю сбросов и missing data, исходы через заранее выбранные горизонты, MFE/MAE и размер выборки. Для имитации торговли учитывать спред и издержки на реальном инструменте, а не только долю положительных исходов.
5. Сохранять все испробованные настройки и проверять на последующих отложенных периодах. Многочисленный перебор вариантов повышает риск подгонки; один удачный участок и один holdout не дают универсального доказательства. [Bailey и соавторы, The Probability of Backtest Overfitting](https://carmamaths.org/resources/jon/backtest2.pdf).
6. Записать forward-наблюдения без реальных ордеров: совпадение уведомлений с графиком, задержку публикации и доставки, число лишних уведомлений. Проверка на истории не воспроизводит автоматически все live-задержки.

Первый полезный результат разработки — одна сквозная редактируемая схема на одной паре: данные → индикаторы → цепочка → объяснение → журнал/тестовый канал, с регрессионными тестами и replay. После него расширять конструктор и число пар. Даже если конкретный шаблон не покажет преимущества, терминал может оставаться полезным как средство мониторинга других проверяемых гипотез; не следует выдавать этот шаблон за доказанную торговую систему.

## Итоговый статус

- **Реализуемость:** да, базовые возможности заложены; точный шаблон требует перечисленных уточнений.
- **Польза мониторинга:** понятна из сценария, фактическое удобство/экономия времени проверяются в работе.
- **Прибыльность и вероятность разворота:** не установлены; численных результатов пока нет.
- **Полное воспроизведение исходного SUI/USDC на Finam:** не подтверждено без того же инструмента и сопоставимых данных.
