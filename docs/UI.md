# Интерфейс TradeMaster

> Актуальное упрощение конструктора: [CURRENT_SIGNALS.md](CURRENT_SIGNALS.md). Пять индикаторов, группы И / ИЛИ, без временных окон и цепочек; две начальные схемы вверх / вниз. Прежние описания этих возможностей ниже относятся к предыдущему объёму.

Дата: 4 ноября 2026 года. Статус: направление для первого макета, без реализации.

## Основная сущность — валютная пара и её сигналы

Пользователь выбирает пару и работает в её собственной области: график, сигналы, состояние условий и события этой пары. Новый сигнал создаётся внутри выбранной пары. Общие шаблоны помогают собрать сигнал, но не заменяют структуру «пара → её сигналы».

Внутренняя модель инструмента остаётся универсальной ради разных поставщиков API. В интерфейсе первой версии основной термин — «валютная пара». Ручная запись пары связывается с реальным кодом провайдера и проверкой доступности данных.

При добавлении/настройке пары выбирается подключение **Finam или iTick**. Каталог загружается от выбранного поставщика; для iTick forex используется `/symbol/list?type=forex&region=GB` с поиском по code. В заголовке графика и событии видно, какой источник используется. Переключение поставщика не изменяет условия сигналов, но требует сопоставления инструмента и нового прогрева, без смешивания свечей. Возможности live зависят от прав подключения; ограничения показываются явно.

**Переключатель есть прямо в терминале:** в шапке пары **«Источник: Finam · Основной ▾»**. Список включает iTick и любые будущие настроенные подключения через общий реестр, с их статусами и переходом в настройки. Он меняет источник выбранной пары, её графика и сигналов; другие пары не переключаются. Индивидуальные флаги сигналов сохраняются, во время загрузки показывается «Переключение / прогрев». Старая история событий остаётся с прежним источником. Общая пара хранит проверенные привязки к кодам разных поставщиков, чтобы после сопоставления не вводить их заново при каждом переключении. Подробнее: [DATA_SOURCES.md](DATA_SOURCES.md).

## Визуальное направление

Скриншот Bybit из корня проекта — **приблизительный визуальный ориентир** по тёмной палитре, типографике и плотности. Точное воспроизведение, поиск идентичного шрифта и копирование продуктовой логики не требуются.

Предлагаемое направление: графитовый фон, немного более светлые панели и поля, белый основной и серый вторичный текст, янтарный акцент, зелёные/красные свечи. Обычный читаемый sans-serif и табличные цифры для цен. Точные оттенки, шрифт и размеры выбираются на макете по читаемости.

Состав действий и навигация определяются задачами TradeMaster. Главная должна помогать наблюдать за парой и её сигналами.

## Готовые компоненты

UI-kit — **Ant Design**: Layout/Menu/Tabs для навигации, Table для справочников и журнала, Form/Input/Select/InputNumber/Switch для настроек, Modal/Drawer для редактирования, Splitter для панелей, Tag/Badge/Alert для статусов. Используется штатная тёмная компактная тема с несколькими изменёнными цветовыми токенами и системным шрифтом.

Вложенные группы И / ИЛИ редактируются через **React Query Builder с Ant Design-интеграцией**. Таймфрейм, индикатор, окно и параметры показателя добавляются через расширения редактора. UI-библиотека не определяет семантику выполнения сигнала.

Свечной график — **KLineCharts** с готовыми финансовыми взаимодействиями, панелями и расширением индикаторов. Точные значения используемых в сигналах показателей приходят из общего вычислительного ядра. Собственный canvas-график не разрабатывается.

Приоритет — готовые рабочие компоненты и простота поддержки. Не требуется отдельная собственная дизайн-система, точная стилизация под Bybit или работа над размером пакета ради самого размера. Причины выбора и ссылки: [STACK.md](STACK.md).

## Главная — рабочая область пары

Верхняя навигация: **Пары · Справочники · История · Настройки**. Библиотека шаблонов доступна из действия создания сигнала.

```text
┌───────────────────────────────────────────────────────────────┐
│ TradeMaster   Пары   Справочники   История   ⚙   Finam: подключён│
├──────────────┬───────────────────────────┬──────────────────────┤
│ Мои пары     │ EUR/USD · цена · статус   │ Сигналы EUR/USD      │
│ Поиск   [+]  │ 5m 10m 15m 30m 1h 1d     │ [+ Создать сигнал]   │
│              ├───────────────────────────┤                      │
│ EUR/USD  ◀   │                           │ Разворот вверх       │
│ GBP/USD      │     Свечной график        │ Включён · 5m/1h/1d   │
│ Другая пара  │     EMA и объём           │ 5m ✓  1h ✓  1d …    │
│              │     Stochastic / MACD     │                      │
│              │     по выбору             │ Другая схема         │
├──────────────┴───────────────────────────┴──────────────────────┤
│ События EUR/USD · время · сигнал · результат · доставка Telegram│
└───────────────────────────────────────────────────────────────┘
```

Названия пар на схеме иллюстративные и не подтверждают их доступность у Finam.

- **Слева:** мои пары, поиск, избранное, цена и статус данных, добавление из каталога или вручную.
- **В центре:** выбранная пара, свечной график, переключение периода, индикаторы, маркеры событий. Панели индикаторов сворачиваются и изменяют высоту.
- **Справа:** только сигналы выбранной пары, включение/пауза, создание с нуля или из шаблона, редактирование, состояние условий с таймфреймами и временами свечей.
- **Снизу:** события этой пары и доставка уведомлений; полный журнал всех пар доступен через историю.

Каждый сигнал принадлежит паре. Применение одного шаблона к двум парам создаёт независимые сигналы с отдельным состоянием и историей. Редактирование одного не меняет другой без явного применения новой версии.

В меню сигнала доступны «Создать вариант» и «Сравнить варианты на истории». Копия имеет собственные настройки и состояние; можно менять И / ИЛИ, состав условий, периоды, пороги, окна, правила запоминания/перепроверки и сброса. Выбранные варианты проверяются на общей выборке с результатами рядом. README — демонстрационный пример, экран создания по умолчанию позволяет собрать собственную схему с нуля.

Переключение пары не выключает мониторинг остальных. Переключение периода графика не меняет таймфреймы условий сигнала: схема 5m И 1h И 1d работает по своим настройкам независимо от открытого графика.

## Переключатели мониторинга

Два уровня управления:

1. **Общий переключатель «Мониторинг» в верхней панели** — запуск/пауза выполнения всех сигналов. Рядом отображаются «Работает», «На паузе» или «Есть ошибки» и число включённых/фактически работающих сигналов. Общая пауза сохраняет индивидуальные переключатели; возобновление возвращает только ранее включённые сигналы.
2. **Переключатель у каждого сигнала выбранной пары** — включить/выключить именно его. Рядом статус: выключен, ожидает запуска мониторинга, прогрев, работает, ждёт подтверждения или причина блокировки. Включённый переключатель означает намерение пользователя, а не гарантирует наличие исправного потока данных.

Например: «EUR/USD → Разворот вверх [вкл.]», «EUR/USD → Мой вариант [выкл.]». При общей паузе первый остаётся выбранным и показывает «Мониторинг на паузе»; второй остаётся выключенным. Переключение пары в списке ничего здесь не меняет.

При первом запуске общий мониторинг выключен. Новый/скопированный сигнал и импортированный вариант создаются выключенными. После перезапуска восстанавливаются индивидуальные настройки; автоматическое возобновление общего мониторинга задаётся отдельной настройкой приложения, по умолчанию выключено. Общая пауза не выключает живой график и не закрывает приложение.

Кнопки «Включить все сигналы пары» / «Выключить все» могут выполнять массовое изменение индивидуальных переключателей. Отдельный третий независимый переключатель пары в первой версии не требуется; массовое включение не снимает общую паузу.

Выключение сигнала или общая пауза прекращает новые проверки и сбрасывает незавершённые цепочки с указанием причины. Возобновление загружает пропущенную историю для прогрева, затем продолжает новые проверки без рассылки событий за время паузы; временная цепочка ждёт нового триггера. Уже сохранённые события остаются в журнале, ранее созданная очередь Telegram обрабатывается по своим правилам: пауза мониторинга не отменяет состоявшиеся события. При необходимости доставка отключается отдельно в настройках уведомлений.

Боковые панели и журнал изменяют размер и сворачиваются; графику отдаётся основная площадь. На небольшом окне правая панель доступна по кнопке. При первом запуске основные действия — подключить Finam, добавить пару, создать её первый сигнал.

## Живой график

Для выбранной пары предусматривается обычный свечной график с обновляемой текущей свечой: REST Bars загружает историю, WebSocket BARS передаёт обновления по инструменту/таймфрейму. Такая подписка предусмотрена Finam. [Документация WebSocket](https://api.finam.ru/getting-started/bystryy-start/poluchat-dannye-cherez-websocket/).

История и поток сшиваются без дублей, после обрыва выполняется сверка. Подписки переиспользуются между графиком и мониторингом; ненужные освобождаются при переключении. Для режима live WebSocket включается в первый релиз, а не откладывается как необязательное расширение.

Текущая свеча изменяется на графике, но уведомления вычисляются только по подтверждённым закрытым свечам. Предварительные значения индикаторов на текущем баре, если показаны, обозначаются отдельно от зафиксированных условий сигнала.

Частота обновления зависит от поступления данных, прав и задержки провайдера. Интерфейс показывает время последнего обновления, рынок закрыт, задержанные данные и потерю связи; при недоступном потоке REST-режим обозначается как периодический, а не полноценный live.

## Настройки и справочники

В **Настройках**: ключи и подключения API, Telegram, общие параметры уведомлений, автозапуск и трей, часовой пояс/масштаб, хранение и диагностика.

В **Справочниках**: показатели и их параметры, доступные/вычисляемые таймфреймы, каталог пар и соответствий кодам поставщика. Добавленная пара появляется в списке «Мои пары».

В **редакторе сигнала пары**: условия И / ИЛИ, вложенные группы, таймфрейм каждого условия, временные подтверждения, повторы и сообщение. Глобальные настройки не подменяют эти параметры.

## Компактный список пар и удаление

Пары в левой панели отображаются компактными строками без круглой буквенной иконки: код, название, счётчик включённых сигналов и цветной чип источника (iTick Trial, iTick или другой поставщик). Полное название источника доступно в подсказке. Кнопка корзины находится отдельно от кнопки выбора пары.

Удаление требует подтверждения с количеством связанных сигналов. Сигналы удаляются вместе с парой, их мониторинг и подписки на данные останавливаются; история событий сохраняется. При удалении выбранной пары выбирается соседняя. Последнюю пару также можно удалить: список остаётся пустым после перезапуска, предлагается добавить новую, общий мониторинг выключается. Настройки и общий журнал остаются доступны.

## Звук срабатывания

В конце настроек, после подключений и Telegram, расположен раздел «Звук»: включение, громкость 0–100% и кнопка «Прослушать». По умолчанию звук включён на 60%. Настройки сохраняются между запусками. Короткий звук воспроизводится при новом сохранённом срабатывании, независимо от Telegram и выбранной пары, в том числе при свёрнутом окне. Системные события и повторное получение снимка состояния не озвучиваются. Ошибка аудио не влияет на вычисление и сохранение сигналов.

## Карточки сигналов

Карточки показывают название, переключатель, таймфрейм, статус и время проверки/последнего срабатывания. Дерево результатов условий доступно в подробностях события в журнале, в карточке его нет. Отступы карточек уменьшены.
